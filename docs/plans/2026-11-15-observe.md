# `ws observe` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ws observe` keeps one observation plan per switched-off job (task), runs each business
day's checks (a database count through a guarded read-only runner, an observability count through
a program the session's tool runs, a manual yes/no), records the values with their real times,
says day k of N, the streak and "pode desligar de vez" or "atenção", and prints the PT-BR evidence
for the GMUD. The `observe` skill drives it; the daily shows one line.

**Architecture:** Three ports with adapters, as `ws.tracker`: `ws.observability` (port, Datadog
adapter and its `execute_code` template), `ws.database` (port, neutral SQL guard, one-number
runner with a lock, Postgres adapter through psql in Docker), and the existing task tracker port
(the title in the report). Neutral flat modules: `ws.contracts` (versioned JSON contracts, shared
with the tracker work), `ws.observedef` (the plan), `ws.observeresults` (the rows),
`ws.observestatus` (business days, windows, streak), `ws.observereport` (PT-BR Markdown) and
`ws.observe_cli`. `ws.workdays` gains holidays; `ws.privatefile` takes the 700/600 helpers out of
`ws.reviewpack`.

**Tech Stack:** Python 3.12+, standard library only at runtime; `uv`, `pytest`, `ruff`; `node`
only for the optional template tests (skipped when absent), as `tests/test_deploycheck.py`.

**Spec:** `docs/specs/2026-11-15-observe-design.md` (all sections). Starts from `main`.

## Global Constraints

- Runtime code: standard library only. Run everything with `uv run` (`uv run pytest -q`,
  `uv run ruff check`, `uv run ruff format --check`).
- Names in English (modules, flags, JSON keys, problems, warnings). PT-BR only in the status text
  line, the report and the skill's lines to the user.
- Provider agnostic: the words `datadog`, `postgres`, `psql`, `docker`, `jira`, `execute_code`
  and the `pg_` prefix appear only in `*_adapter.py`, `src/ws/data/datadog_count.js`, their tests
  and config examples. Help text and the skill say "task", "task tracker", "observability tool",
  "database". The `open_*` functions import adapters by name (`importlib`), never at module top.
- Every exchanged document carries `"version": 1` and validates against its schema in
  `src/ws/data/contracts/` through `ws.contracts.validate`.
- `ws observe` never writes to the task tracker, the database or the observability tool; it
  reaches a database only through `ws.database.scalar`; it never reads the pgpass file nor
  `~/.config/workspace/credentials`; database stderr is never printed or stored.
- Files only under `config.data_dir()`; tests set `WS_DATA_DIR` and `WS_CONFIG_DIR` to `tmp_path`.
- Tests: no Docker, no network, no real observability tool, database or tracker; subprocess calls
  go through an injected `run`; fake tasks `TS-5`, `TS-6`; projects `demo`, `other`; host
  `db.invalid`; switch-off `2026-12-08` (a Tuesday): days 1 to 5 are 09, 10, 11, 14 and 15/12.
- Commits: prefix `feat:`, `fix:`, `test:`, `docs:` or `chore:`, PT-BR, at most 72 characters, no
  task ID, no `Co-Authored-By`; `git diff` before each message. Each task commits in its own
  worktree branch; the controller merges and pushes.

## Review Focus

1. A SQL with two statements, a `;` inside a literal or a quoted identifier, a write hidden in a CTE (`with x as (delete ...) select`) or `select ... into`: one refused, the other accepted, before any run (Tasks 3, 6).
2. A query that returns rows, two columns, null or text instead of one number: refused by the adapter's wrapper or by `scalar`, with a fixed reason and no value from stderr in any output (Tasks 3, 6).
3. A `--day` on a weekend, on a holiday (25/12/2026), on the switch-off day or today (window still open): exit 1 naming the next business day or the latest closed one, nothing run or written (Tasks 5, 6).
4. A rerun on the same day, and a `record` after the plan was edited: one row per day and check; an old hash refused; earlier rows stale and out of the streak (Tasks 2, 5, 6).
5. A plan created after some days already passed: `missing_days` from day 1, `run --day` backfills, a snapshot SQL warns on a past day, and the streak starts only from a complete day (Tasks 5, 6).

## Parallel waves

- Wave 1 (5 agents, disjoint files): Task 1 (contracts, no dependency), Task 2 (plan and rows),
  Task 3 (database port), Task 4 (observability port), Task 5 (business days, status, report).
  Tasks 2 to 5 work on plain dicts shaped as the contracts in the spec; validation is wired in
  Task 6.
- Wave 2 (3 agents, disjoint files): Task 6 (the CLI; consumes 1 to 5 and Task 8's
  `bootstrap.observe_gate_problems`), Task 7 (skill, daily, change request, README; consumes the
  commands and JSON keys as written here) and Task 8 (the approval gate for database checks).

### Task 3: The database port, the SQL guard and the Postgres adapter

**Files:**
- Create: `src/ws/database/__init__.py`, `src/ws/database/port.py`, `src/ws/database/guard.py`,
  `src/ws/database/postgres_adapter.py`

**Interfaces:**
- `ws.database.port`: `class Setup(Exception)` (exit 2), `class Unreachable(Exception)` (3),
  `class Refused(Exception)` (1), `class Busy(Exception)` (1); `@dataclass(frozen=True) class
  Rules: words: tuple[str, ...] = (); prefixes: tuple[str, ...] = (); marks: tuple[str, ...] =
  ()`; `@runtime_checkable class Database(Protocol): name: str; timeout: int; rules: Rules; def
  scalar_text(self, sql: str, bounds: dict[str, str], timeout: int) -> str: ...`.
- `ws.database.guard`: `WORDS = ("insert", "update", "delete", "merge", "truncate", "drop",
  "alter", "create", "grant", "revoke", "call", "execute", "set", "reset", "lock", "begin",
  "commit", "rollback", "savepoint", "into", "replace")`; `PLACEHOLDERS = ("day", "day_from",
  "day_to")`; `split(sql: str) -> list[tuple[str, str]]` (pieces `code`, `literal`, `identifier`;
  `''` and `""` escapes; unclosed → `Refused("unclosed literal or quoted identifier")`);
  `guard(sql: str, rules: Rules = Rules()) -> tuple[str, tuple[str, ...]]` (the SQL without its
  last `;`, and the placeholders used, in `PLACEHOLDERS` order). Placeholders are
  `(?<!:):([A-Za-z_]\w*)` in code pieces (`x::numeric` is a cast); another name → `Refused(
  "unknown placeholder :<name>; use :day, :day_from or :day_to")`. Words compare lowercased, whole
  words, code pieces only. Other refusals: `the query is empty`, `comments are not allowed`, `only
  one statement is allowed`, `the query must start with select or with`, `"<word>" is not allowed
  outside a literal`, `"<mark>" is not allowed`, `words starting with <prefix> are not allowed`.
- `ws.database`: `engines() -> tuple[str, ...]` (the `*_adapter` modules of the package, through
  `pkgutil.iter_modules`, sorted, suffix removed); `open_database(name: str) -> Database`
  (`userconfig.load_table("database")[name]`; absent or `ConfigMissing` → `Setup("[database.<name>]
  is missing in config.toml")`; `engine` not in `engines()` → `Setup("database.<name>.engine must
  be one of: <list>")`; `importlib.import_module(f"ws.database.{engine}_adapter").from_config(
  name, table)`); `scalar(db: Database, sql: str, bounds: dict[str, str], *, lock: Path | None =
  None) -> Decimal` (guard with `db.rules`; an exclusive non-blocking `fcntl.flock` on `lock` or
  `data_dir() / "observe.lock"` (600) → `Busy("another ws observe run holds the database lock")`;
  passes only the placeholders used; output stripped: one line matching `-?\d+(\.\d+)?` →
  `Decimal`; nothing → `Refused("the query returned null; wrap the aggregate in coalesce(..., 0)")`;
  anything else → `Refused("the query must return one number")`).
- `ws.database.postgres_adapter`: `REFUSED = Rules(words=("copy", "do", "vacuum", "analyze",
  "listen", "notify", "prepare", "discard", "load", "comment", "set_config", "nextval", "setval",
  "dblink"), prefixes=("pg_", "lo_"), marks=("\\", "$"))`; `NOT_REPLICA = "ws-not-a-replica"`;
  `REASONS: tuple[tuple[str, type[Exception], str], ...]` (stderr fragment, exception, fixed
  text); `@dataclass(frozen=True) class Postgres: name: str; timeout: int; replica_only: bool;
  host: str; port: int; database: str; user: str; pgpass: Path; runner: str; image: str;
  docker_args: tuple[str, ...]; rules: Rules = REFUSED; run: Callable[...,
  subprocess.CompletedProcess] = subprocess.run`; `from_config(name: str, table: dict) ->
  Postgres` (keys `engine`, `timeout_seconds` (default 120, 1 to 600), `replica_only` (default
  true), `host`, `port` (1 to 65535), `name` (the database name), `user`, `pgpass` (default
  `~/.pgpass`, expanded), `runner` (`docker` default, or `local`), `image` (default
  `postgres:16`), `docker_args` (list of strings); a bad or unknown key → `Setup` naming
  `database.<name>.<key>`); `command(self, bounds: dict[str, str]) -> list[str]` (docker: `docker
  run --rm -i`, the `docker_args`, the pgpass mounted read-only at `/tmp/pgpass` and named by
  libpq's password-file variable, the image, then `psql -X -q -A -t -v ON_ERROR_STOP=1 -h <host>
  -p <port> -U <user> -d <database> -f -` and one `-v <name>=<value>` per bound; local: the same
  psql argv, the variable set in the child's environment); bound values must be an ISO date or
  an ISO date-time with offset, else `ValueError`; `script(self, sql: str) -> str` (`SET
  statement_timeout = '<timeout>s';`, `BEGIN TRANSACTION READ ONLY;`, with `replica_only` `SELECT
  pg_is_in_recovery() AS ws_replica \gset`, `\if :ws_replica` ... `\else` `\echo
  ws-not-a-replica` `\endif`, inside it `SELECT (` + the SQL with `:day_to` rewritten to
  `:'day_to'` (code pieces only, through `guard.split`) + `)::numeric;`, then `ROLLBACK;`);
  `scalar_text(self, sql, bounds, timeout) -> str` (pgpass must exist (`Setup`, the file is never
  opened); one `run` call with `input=script`, `capture_output=True`, `text=True`,
  `timeout=timeout + 30`; `FileNotFoundError` → `Setup("<runner> not found")`; `TimeoutExpired` →
  `Unreachable("the query timed out")`; stdout `ws-not-a-replica` → `Setup("database.<name> is not
  a read replica")`; a non-zero exit → the first `REASONS` match, else `Unreachable("the database
  refused the query")`; stderr never kept in an exception or `__context__`).
- `REASONS` at least: `statement timeout` → `Unreachable` timed out; `could not connect`,
  `could not translate host`, `Connection refused`, `timeout expired` → `Unreachable` unreachable
  (VPN or port); `password authentication failed`, `no password supplied` → `Setup` login refused
  (check the pgpass entry); `Cannot connect to the Docker daemon` → `Setup`; `more than one row`,
  `must return only one column` → `Refused` one number; `invalid input syntax for type numeric`,
  `cannot cast` → `Refused` not a number; `syntax error` → `Refused` syntax error;
  `permission denied` → `Unreachable` refused.
